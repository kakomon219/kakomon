## ■ 今回(2026-08-10)実施した内容

### ① 画面フローの全面刷新

旧: 資格トップに級・テーマ絞り込みタブ+問題カード一覧が並ぶ
新: 資格トップはモード選択ボタンのみ。以下の段階フロー

```
[新しい問題][続きの問題][間違えた問題][問題一覧を見る]
  ↓ 新しい問題・問題一覧を見る の場合
級を選ぶ → テーマを選ぶ → 確認パネル
  ↓ 続きの問題・間違えた問題 の場合
(選択不要) → 確認パネル
  ↓
確認パネルに「次に解く範囲(級/テーマ)」「対象○問」「最初の問題」を表示
  ↓ ここから始める
1問目にジャンプ → 「次の問題へ」で一問一答ループ
```

対象問題はURLの `ids` パラメータ(カンマ区切りのid列)で受け渡し。
`[id]/page.tsx` は `ids` があればその中で次・前・問題番号を計算、
無ければ従来通りtheme内ループ。

### ② 中止・再開機能

- 解答前・解説表示後の両方に「中止する」ボタンを配置
- 中止時、localStorage `kakomon_resume_<資格名>` に保存
  - 解答前の中止 → その問題を保存
  - 解答後の中止 → **次の問題**を保存(最終問題なら記録削除)
- 「続きの問題」で再開記録があればそこから再開
- 確認パネルに「最初から始める」ボタンも併設

### ③ 選択肢シャッフルの限定化

正解番号の偏りを実データで確認した結果:

| 対象 | 偏り |
|---|---|
| 漢字検定3〜7級 | 各110問中、正解1が101〜104問 |
| 食生活3級オリジナル問題 | 正解1〜3が0問、4が8問・5が12問 |

→ `shuffle_choices` 列を追加し、上記2群のみtrue。他は原順表示に変更。
「該当なし」の選択肢はシャッフル対象外で常に最後尾固定。

```sql
ALTER TABLE questions ADD COLUMN shuffle_choices boolean NOT NULL DEFAULT false;

UPDATE questions SET shuffle_choices = true
WHERE qualification = '漢字検定'
   OR (qualification = '食生活アドバイザー' AND exam_round = '3級オリジナル問題');
```

### ④ 解説内の選択肢番号を丸数字に統一

シャッフル時に番号がずれるため、以下を一括UPDATE(計326件)

```
選択肢1→選択肢①   正解:1→正解:①   正解は1→正解は①
1は誤→①は誤      1が正→①が正     肢1→肢①   は1です→は①です
```

※英検の「1番目/2番目」は語順を指すため変換対象外
 (WHERE句に `AND explanation NOT LIKE '%番目%'` を付けて除外)

### ⑤ その他修正

- `lib/supabase.ts` v0.6でSupabaseクライアントのfetchに `cache: "no-store"` を明示
  (DB更新がアプリに反映されない問題を解消)

```ts
export const supabase = createClient(supabaseUrl, supabaseAnonKey, {
  global: {
    fetch: (url, options) => fetch(url, { ...options, cache: "no-store" }),
  },
});
```

- 全問題に `question_no` を採番(未設定の問題が `No.-` 表示になっていた)

```sql
UPDATE questions AS q
SET question_no = sub.rn
FROM (
  SELECT id, ROW_NUMBER() OVER (
    PARTITION BY qualification, exam_round ORDER BY id
  ) AS rn
  FROM questions WHERE question_no IS NULL
) AS sub
WHERE q.id = sub.id AND q.question_no IS NULL;
```

- 建築施工管理技士一級の建築学(必須)/(選択)を「建築学」1本に統合

## ■ 開発ルール

- コード変更はファイルヘッダー(ファイルパス/バージョン/更新日/内容)付きの全文提示
- バージョンはファイルごとに個別採番(まとめない)
- 「解説ありきのアプリ」が設計思想の核。解説の質は絶対に妥協しない
- 解説は選択肢ごとの正誤理由+専門用語の定義+rubyふりがな付き
- **オリジナル問題作成時は正解番号を意図的に散らすこと**
  (過去に特定番号への集中が発生したため)
- 重複削除時はattemptsが外部キー参照しているため、先にattemptsを削除する
- 重複確認SQL:

```sql
SELECT qualification, exam_round, theme, question_text, COUNT(*)
FROM questions
GROUP BY qualification, exam_round, theme, question_text
HAVING COUNT(*) > 1;
```
