### 1-5. 問題番号の採番

各年度とも実際の出題順(問題1→6)で通し番号を付与済み。採番SQLは以下の形式。

```sql
UPDATE questions AS q
SET question_no = n.rn
FROM (
  SELECT id, row_number() OVER (
    ORDER BY
      CASE theme
        WHEN '施工経験記述(品質管理)' THEN 1
        WHEN '仮設物計画' THEN 2
        WHEN 'ネットワーク工程' THEN 3
        WHEN '躯体工事の留意事項' THEN 4
        WHEN '五肢択一(数値・語句)' THEN 5
        WHEN '法規(五肢択一)' THEN 6
      END, id
  ) AS rn
  FROM questions
  WHERE exam_round = '令和5年度 第二次検定'
) AS n
WHERE q.id = n.id;
```

themeのCASE句は年度により異なる(令和6年度は「施工経験記述(生産性向上)」「設備・機械の安全使用」「仕上げ工事の留意事項」)。

## 3. 次回同じ作業をするときの要領

### 3-1. データ入手

**PDFのテキスト抽出は使わない。** ふりがな付き縦組みが1文字ずつ分解されて崩れ、問題文冒頭や選択肢の丸数字が欠落する。今回これで一度誤った登録をしかけた。

→ **スクリーンショットを送ってもらう**のが確実。設問文と選択肢表の両方が写っていること。

### 3-2. 記述式(essay)のmodel_answerの構成

4部構成で統一する。

1. **【解答例】** — その2つを書けばよい、という完成形。理由まで含める
2. **【1】法令・数値の根拠** — 条番号、管理値、なぜその数値なのかの理屈
3. **【2】他に書ける切り口(引き出し)** — 解答候補を5〜8個。本番で「異なる内容を2つ」の条件をクリアするため
4. **【失点に注意】** — 設問の除外条件に抵触する具体的NG例

### 3-3. 除外条件は年度・設問ごとに違う

第二次検定の記述式は「〜に関する記述は除く」という制約が必ず付く。これを外すと0点になるため、登録時に必ず設問文から拾って【失点に注意】に反映する。

実例:

- 令和7年度 問題2:申請手続、届出、仮設物設置後の運用管理
- 令和6年度 問題2:保護具の使用、気象条件、資格、免許、届出。さらに「2.を除き保守点検に関する記述は不可」(仮設電力設備のみ点検を書ける)
- 令和6年度 問題4:材料(仕様、品質、搬入等)、作業環境(騒音、振動、気象条件等)、清掃、安全。設問ごとに追加除外あり(1.は割付け・材料保管・下地、2.は材料保管・防水層、4.は下地)
- 令和5年度 問題4:材料(仕様、品質、搬入、**保管**等)、作業環境、**養生**、安全。1.のみ地下水の処理・設置後の維持管理も除外

### 3-4. 選択肢問題(choice)の解説

既存方針どおり、各選択肢の正誤理由+専門用語の定義+rubyふりがな。第二次検定では以下も加える。

- なぜその数値なのかの理屈(例:壁つなぎが単管5m・枠組9mなのは、枠組の建枠が面として剛性を持つため)
- 混同しやすい類似概念との対比(例:ヒービングと盤ぶくれ、打重ね時間間隔と練混ぜから打込み終了までの時間)

### 3-5. アップロード画面の仕様

`app/admin/upload/page.tsx` の一覧は **needs_image=true かつ image_url未設定** の問題だけを表示する。INSERT時にneeds_imageを指定し忘れると一覧に出ないため、図表が必要な問題は登録時に `needs_image = true` を入れること。
